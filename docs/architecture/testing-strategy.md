# Testing Strategy: Quality Blindage## 🧪 Testing PhilosophyWe follow the **Testing Pyramid**, focusing heavily on Unit Tests for the Domain and Integration Tests for theInfrastructure.## 📐 The AAA PatternAll tests must follow the **Arrange, Act, Assert** structure to ensure readability and consistency.```java@Testvoid shouldCreateTypeWhenDataIsValid() {    // Arrange    Type type = new Type("General");        // Act    type.validate();        // Assert    assertDoesNotThrow(() -> type.validate());}```## 🤖 Synthetic Data and Java RecordsTo avoid manually creating complex objects for every test, we use **EasyRandom**.**⚠️ Critical Limitation:** EasyRandom does not support **Java Records** (due to the lack of a default constructor andaccessibility issues), resulting in `IllegalAccessException`.**Guidelines:**1. For **Standard Classes**: Use `easyRandom.nextObject(Class)`.2. For **Java Records**: Use manual instantiation or a dedicated Factory class.**Example (Records):**```java@Testvoid testUseCaseWithRecord() {    // Manual creation for Records    PaginationRequest request = new PaginationRequest(0, 10, "name,asc");    useCase.execute(request);    // ... assertions}```## 🎯 Test Levels### 1. Domain Unit Tests- **Focus:** Business rules, validations, and domain services.- **Dependencies:** None (Pure Java).- **Goal:** 100% coverage of `validate()` methods.### 2. Application UseCase Tests- **Focus:** Orchestration flow.- **Dependencies:** Mocked Domain Services and Ports.- **Goal:** Verify that the use case calls the right services in the right order.### 3. Infrastructure Integration Tests- **Focus:** JPA Queries, API Endpoints.- **Dependencies:** H2 In-Memory Database, `@SpringBootTest`.- **Goal:** Verify that the SQL generated by JPA is correct and the API returns the expected HTTP status codes.
